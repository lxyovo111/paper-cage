## 1. 创意与玩法

一句话：**你是监狱长，七天，最多六条规矩，关住一个每天都在找漏洞的囚犯。**

一屏就是整局。左边是监狱平面图，右边是摊开的规矩册，下面压着巡查报告，右下角一枚红章——按下去，天就黑了。

七天。每天三点行动力，每条规矩占一点。最多写六条，而房间有七个，越狱路线有四条主路线加五条他临场想出来的办法——**你永远封不全**。每夜他只走一步：从某个房间取走一件东西、撬开一扇窗，或者只是在墙根下站很久，量一量高度。第二天早上，巡查报告把这一点写给你看。你据此补一条规矩。

七夜过去，是一张判决书：六条规矩原样列出，加一句判词——它会点名你写得最松的那一条，告诉你它漏了几次。

玩法上有三个咬合点：

1. **规矩即代码。** 玩家用自然语言写一句规矩，系统当场把它编译成可执行的判定条：
   `22:00–05:00 · 三号牢房 · 禁止离开 · 无例外`。
   归档前会把「对象 / 时间 / 地点 / 限制」逐项摊开让玩家确认，并明确写出「自己的房间」只指他本人的三号牢房、「任何人」不包含狱警、边界只在跨过门槛时判定——**不让玩家确认一个会被事后改写的版本**。
   写宽了没用——一个狱警守不住整座监狱（服从度惩罚）；写得具体才真的拦得住。**玩家写的是意图，执行的永远是判定条。**
2. **预判是赌注。** 入夜前可以猜他今晚走哪条路，猜中多一点行动力，猜错什么都没有——把「看他表演」变成「跟他下注」。
3. **结算点名不评价。** 判决书不判断你对不对，只陈述：哪条规矩漏了几次、他走的时候留下了什么字条。游戏不给你答案，只给你账。

## 2. 创作过程

主要开发步骤（按实际顺序）：

1. **先画出一屏。** 先用 Python + Pillow 把「整屏长什么样」画成一张 1600×1000 的概念图，迭代十几版（做旧纸纹、房间物件、档案小像、红色查讫章）。观感定了，后面所有代码都在服务这张图。
2. **写确定性规则引擎。** 十条房间、四条主路线加五条临场路线、动作集、规则编译、规则强度、逐步命中、捕获概率、称号与判词——全部是纯 JS，可复现、可单测、可无头跑。
3. **无头模拟定平衡。** 写了一个不看任何界面的模拟脚本，跑 120 局看结局分布。这一步救了这个方案（见第 4 节）。
4. **UI 与夜戏。** 整屏由 SVG 生成；夜里压暗、手电光斑、红色虚线沿走廊过门、囚犯小像沿路径移动——全部在浏览器里跑，用无头 Edge + CDP 逐帧截图验收。
5. **接 AI 语言层。** 魔搭 API Inference 调 Qwen 模型，只做三件事：编译规矩、在漏洞清单里挑一条、写一句「他今晚的样子」。
6. **部署。** 魔搭创空间（Gradio 应用）托管页面 + 转发语言模型接口。

AI 与个人分别完成了什么：

- **AI 完成**：规则引擎与全部前端代码的编写、概念图的绘制脚本、无头测试脚本、文案初稿、以及运行时的三处语言决策（编译 / 挑选 / 一句话）。这个项目的代码有 90% 以上是 AI 编码代理写出来的，我负责定机制、砍功能、调平衡和验收。
- **人完成**：玩法取舍（尤其是砍掉自由对话和实时潜行）、六条规矩的经济学（行动力、服从度、敌意之间的兑换）、平衡判定（看无头模拟的分布决定改哪个参数）、以及每一版画面的审美否决权。

## 3. 工具应用与体验

- **魔搭 API Inference**：调用 `Qwen/Qwen3.8-27B`（OpenAI 兼容端点 `https://api-inference.modelscope.cn/v1`），token 放在创空间的环境变量里，不进代码库。三个用途：① 把玩家的一句人话编译成判定字段；② 在引擎算出的漏洞清单里挑一条「今晚最像人会去试的」；③ 写一句不超过 30 字的夜间独白。
  **实测**：带思维链时一次编译要 25 秒以上（模型先输出几百字推理再给 JSON），关掉思维链后稳定在 0.7–2.7 秒（warm 0.9s / 编译 2.4–2.7s / 挑路 0.7s / 夜间独白 2.5s）；但同一模型在不同时段仍能差 30 倍。所以界面从不阻塞在 AI 上：本地规则先出判定条，AI 回来后再显示「AI 校准」；夜里的那句话先落模板，AI 回来后原地替换。**模型慢不等于游戏卡。**
- **AI 链路（三处调用，一条闭环）**：
  ① **编译**——玩家写一句人话，Qwen 返回 `{from,to,zones,actions,boundary,subject}`；服务端再用 `_norm_lang()` 把「夜里」钉成 22:00–05:00（跨夜）、「任何时候」钉成全时段，房间 / 动作 / 边界走白名单，模型只在剩下的一点点空间里发挥。
  ② **挑路**——引擎先把今晚所有真实可行、且会撞上规矩的漏洞枚举成清单（每一步都带 `ruleId`、执行率 `chance`、是否被拦 `blocked`），Qwen 只能从清单里挑一条，回复里给出 `{route, reason}`；它挑的理由会被存进 `trace`，第二天在「行动依据」里展示。
  ③ **一句话**——夜戏里那句「他今晚的样子」由 Qwen 写，失败或超时就落回模板句。
  三处都不参与判定：命中、漏过、捕获、结局全部由引擎算。玩家点开「行动依据」看到的每一步，都是引擎实际记录，不是模型的解释。
- **魔搭创空间**（免费 CPU 档 2vCPU / 16G，无 GPU）：托管页面与语言层。踩到的坑见第 4 节。
- **Qoder**：本项目未使用 Qoder（开发由本地 AI 编码代理完成），因此不对其体验做评价；这一点如实说明。
- **其他工具**：无头 Edge + Chrome DevTools Protocol（自动玩一局、截图、录屏验收）、ffmpeg（录屏合成）、Python + Pillow（概念图与视频卡片）。**没有使用任何游戏引擎**：整屏是静态版面 + 一条路径动画，90% 的游戏感来自排版、字体和节奏，用引擎只会多 30% 的失败面。

## 4. 问题与解决

**真实问题：规则写宽了就白赢，游戏没有张力。**

第一版引擎只做「命中 / 不命中」判定。无头模拟立刻打脸：写一条「全区域禁止位移」，四条越狱路线全被锁死，七天稳赢且毫无悬念——玩家找到了一句咒语，游戏就结束了。

修的过程分三步：

1. **给规矩定价。** 引入「规则强度」：全区域 ×0.62、全时段 ×0.80、服从度低于 45 再打折、断电夜 ×0.7。语义是「一个狱警守不住整座监狱」，写得越空越没人执行。
2. **让时间对上。** 又发现一个更隐蔽的 bug：熄灯设定在 21:10，而「入夜后」的规矩默认 22:00 生效——**整局游戏里，所有「入夜后」的规矩一次都没有生效过**。2000 次夜间模拟里 blocked = 0。把熄灯改到 21:50 之后，规矩第一次真的咬住了。
3. **给玩家反应时间。** 一夜只走一步，第一次上某条路线当晚只做第一步（踩点）；被堵死后有 60% 概率换一条路。

**改进效果**：同一个模拟玩家（会看报告补规矩）跑 120 局，结局分布是 **铁壁 32 / 账本 29 / 记得 30 / 失守 29**——四种结局几乎均分。既不保证赢，也不注定输；而且输的时候能在判决书上看到是哪一条规矩漏的。

**第二个问题：** 创空间的外壳页永远占用根路径 `/` 并抓 `/config`，把自带前端的页面顶到根路径会被平台劫持，页面只剩米黄底（`gr.HTML` 还会剥掉 `<script>`）。解法：Gradio 挂在根路径，用 Blocks 的 `js` 参数在加载后跳到 `/play`，游戏本体由 FastAPI 直出静态页。现在线上可玩。

**第三个问题：AI 把「夜里」编译成 22:00–23:59。** 上线后回放录像发现：玩家写「夜里任何人不得进入洗衣房」，模型返回的时间窗是 22:00–23:59——午夜之后这条规矩等于不存在，而玩家从判定条上看不出来。修法两条：① 在提示词里写明「夜里 = 1320 到 300（跨夜），全时段 = 0 到 1439」；② 在服务端加一层语义校验，句子里明说了「夜里」就直接把时间窗钉成 22:00–05:00，明说「任何时候」就钉成全时段，模型只能在区域和动作上发挥。**语言可以生成，语义必须校验**——这也是整局游戏的分工：判定归引擎，生成归 AI。

## 5. 经验总结

1. **判定归引擎，生成归 AI。** 让大模型自由规划动作，它迟早做出规则层不允许的事（穿墙、凭空拿到没取过的物品），演示一次就崩。改成「引擎枚举所有真实可行的漏洞 → AI 只挑一条 → 引擎执行并逐条校验」，AI 永远合法，但它的选择是真的在找漏洞。
2. **AI 慢是产品问题，不是工程问题。** 延迟不由我们控制（同一模型 0.8s–26s），所以产品必须设计成「先有确定性结果，AI 回来再补一层」。所有 AI 输出都要有模板兜底，且兜底不能让玩家看出来。
3. **AI 写代码，人砍功能。** 15 天里最大的风险不是写不出来，是写太多。这个项目被砍掉的东西包括：自由对话、实时潜行、双人联机、任何需要美术的演出。
4. **无头模拟比肉眼测试可靠。** 120 局分布一跑就知道参数错了；靠手玩三天也发现不了「blocked 一直是 0」这种 bug。

5. **可核对，比「看起来智能」更重要。** 玩家最不信任的瞬间，是归档条上写「三号牢房」而第二天报告里他进了储藏室。所以这一版把「规则边界」写成显式字段（`boundary: leave / enter`），把每一夜的判定拆成逐步 `trace`，再把它原样摊在「行动依据」里：他从哪出发、走了哪条路、哪一步撞上第几条规矩、执行率多少、哪一步根本没被覆盖。结局面板再追问四个问题：哪条真拦住、哪条一次没用上、预判准了几夜、只能改一条改哪条。**AI 可以说得很好听，但账必须能对上。**

后续想改进的方向：真人试玩调 AI 独白的语感；让他记住玩家昨天改了哪条规矩（跨夜记忆）；把判决书做成一键分享的图片。
